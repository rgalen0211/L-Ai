# The live editor on the person's computer: what the maker serves and what the page expects (WEB 152 / CONNECT 142)

Status: built on L-Ai branch `live-editor`, off. Nothing serves it yet: the maker (CONNECT, branch `maker-live`) adds the routes below. Design on the maker's side: `proposals\CONNECT-LIVE-EDITOR-DESKTOP.md`.

## 1. The files (all in `tools/maker-live/`)
| file | what it is |
|---|---|
| `live.html` | the page. Its own strict policy in a `<meta>`: `default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'; base-uri 'none'; form-action 'none'`. No inline script, style or handler. (`frame-ancestors` can not be set from a `<meta>`; send `Content-Security-Policy: frame-ancestors 'none'` as a response header if wanted.) |
| `live.js` | GENERATED by `node tools/build-maker-live.mjs` from the website's own `assets/app-editor-core.js`, `-progress.js`, `-draft.js`, `app-editor.js`, then `tools/maker-live/live-host.js`. `tests/maker-live.test.mjs` fails if the committed file differs from the generator's output, so the PC's editor can not drift from the site's. |
| `live.css` | GENERATED: `live-base.css` (the base the site's stylesheet gives) then `assets/app-editor.css`. Dark only. Loads nothing (no `@import`, no `url()`). |
| `live-host.js`, `live-base.css` | the two hand-written sources (the host seam; the base styles). Only these are edited by hand. |

Serve `/live` (the html), `/live.js`, `/live.css` with `charset=utf-8` and `Cache-Control: no-store`, behind the same `X-Maker-Token` check as `/edit`.

## 2. The address
`/live?t=<maker token>&mode=compilation|data&project=<id>` (`mode` other than `data` means `compilation`; `project` is any string up to 64 characters, passed back to you unchanged as `p_project`). The page keeps the token in `sessionStorage` (the key `maker-token`, as `tools/maker-edit/edit.js` does) and removes `t` from the address bar at once. It is then sent only as the `X-Maker-Token` header.

## 3. The host seam
```
window.ryagramLiveHost = { rpc, mode, project, media, title }
rpc(name, args) -> Promise<{ data, error }>        error = null | { code, message }
```
`rpc` is `POST /api/live/rpc` with a JSON body `{ "name": "...", "args": { ... } }` and the header `X-Maker-Token`. You answer `200` with JSON `{ "data": ..., "error": null }` or `{ "data": null, "error": { "code": "PT409", "message": "..." } }`. A network failure or a non-JSON answer reads on the page as "The Ryagram app on this computer did not answer."
Only these five names are ever sent (any other name throws before a request is made): `my_edit_ops_since`, `editor_apply_ops`, `editor_undo`, `editor_undo_all_ai`, `editor_heartbeat`, with CONNECT's argument names (`p_project`, `p_mode`, `p_base_revision`, `p_ops`, `p_revision`, `p_op_id`) and the answers and codes of the SQL (`tests/fake-editor-rpcs.js` is the stand-in): `PT409` stale, `PT403` not shared / not mirrored, `PT404`, `22023` refused (the message is shown to the person in plain words), `PT429`.
`media` is `null` today (a later hook for the maker's media list); `title` is empty (the page says "Edit your film").

## 4. What the page does, so you can rely on it
* **The person's change goes to the PC first.** `editor_apply_ops` with `p_base_revision` = the revision the page last saw; the screen changes only when the answer is accepted. A change sent before the first `my_edit_ops_since` has answered waits for it.
* **It polls** `my_edit_ops_since(p_revision = last seen)` about every 2 s while the tab is visible, and sends `editor_heartbeat` about every 15 s. Rows with `actor: "ai"` that are `applied` or `pending` are applied as steps tagged "by your AI"; rows the person's own page sent are matched to their server ids (needed for `editor_undo`).
* **A track summary** (`state` of the compilation draft, schema `ryagram.edit-tracks/0`) replaces the clips when the revision moves without ops explaining it: `{ duration, lanes?, limits?: { text_chars }, clips: [{ id, track, start, len, label, text?, picture?, source?, source_start?, min_len?, max_len?, ai_altered?, ai_altered_by? }] }`. `lanes` lists what the maker can build (an edit in another lane is refused on the page and the lane is drawn "Not available yet"); no `lanes` means nothing is hidden. `limits.text_chars` is the text field's maximum.
* **Never set by the page:** `source`, `source_start`, `ai_altered`, `ai_altered_by` (read-only; a trim moves `source_start` and `max_len` together, see the vectors). Speaker, voice, cast and face fields (the list is `local_only_fields` in the vectors) are stripped if they arrive.
* **Local only:** nothing is requested from any address but the host's; no storage but the token in `sessionStorage`; no cookie.

## 5. The op vectors (for the Python twin)
`tests/edit-vectors.json`, generated by `node tools/make-edit-vectors.mjs` from `assets/app-editor-core.js` (the file fails its test if it is stale): `{ what, look_keys, ops, min_len_default, local_only_fields, cases: [{ name, state, state_before, op, refusal | state_after }] }`. `state_before` and `state_after` are the whole state `{ look, clips (list order), duration, revision, lanes?, limits? }`; an accepted op gives `revision + 1`; a refusal is the exact sentence the page shows. Port the sentence, not a paraphrase.

## 6. What `app-editor.js` takes from the website's shell (everything the maker's page therefore has to supply or can do without)
| takes | on the PC |
|---|---|
| the element builder `h(tag, attrs, ...children)` | `live-host.js` supplies its own |
| `window.ryagramStart` (`chatUrl`, `APPS`) for the Ask my AI chat links | absent: the box offers Copy only |
| the site's router, `#/` links, the data layer (`data.editorRpc`), Supabase, config, `localStorage` | none; the host's `rpc` replaces the data layer |
| the shell's CSS classes (`.button`, `.button.primary`, `.form-note`, `.meta`, `.container`, the colour variables) | `live-base.css` carries its own |
| `document.hidden`, `navigator.clipboard`, `history.replaceState`, `sessionStorage` | the browser |
| mock helpers (`window.ryagramMock*`) | never present; the "(mock)" buttons do not appear |
